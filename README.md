# Family Budget MVP

Mobile-first MVP без бэкенда: все данные хранятся локально в IndexedDB.

## Архитектура

- `src/store` — инициализация/миграция IndexedDB (`schema.ts`) и seed (`seed.ts`).
- `src/services` — слой доступа к данным и внешним API (курсы валют).
- `src/store/BudgetContext.tsx` — единый state-контейнер (React Context), чтобы потом заменить источник данных на API/синхронизацию.
- `src/pages` — страницы `Расходы`, `Статистика`, `Настройки`.
- `src/components` — форма расхода, список расходов, управление категориями.
- `src/types` — доменные типы.

## Что реализовано

- Без логинов/аккаунтов, persist в IndexedDB.
- Сущности Expense/Category/Settings.
- CRUD расходов, группировка по дням, edit/delete.
- CRUD категорий, безопасное удаление: при наличии связанных расходов категория архивируется.
- Статистика: по категориям, по дням недели (будни/выходные), по месяцам выбранного года.
- Фильтры периода: week/month/year/last30.
- Конвертация валют через Frankfurter API, кэш курсов в IndexedDB на 12 часов.
- Fallback при недоступности API: последний кэш или суммы без конвертации + warning.

## Seed и инициализация

Инициализация происходит в `initializeDB()`:
- создаются стартовые категории,
- создаются настройки валют,
- добавляется demo-расход,
- ставится маркер `meta.seeded`, чтобы seed не повторялся.

## Запуск

```bash
npm install
npm run dev
```

## Точки расширения (для будущих аккаунтов/синхронизации)

1. Слой `services/db.ts` можно заменить на `services/repository.ts` с двумя провайдерами:
   - local (IndexedDB),
   - remote (REST/GraphQL).
2. `BudgetContext` уже работает через абстрактные методы (CRUD + settings + rates), поэтому UI можно оставить без переписывания.
3. Добавить `syncQueue` store в IndexedDB для офлайн-синхронизации и conflict resolution.
4. Для авторизации добавить `auth context` и прокидывать `userId` в ключи коллекций/запросы.
